# Design Specs

Use this directory for design notes and implementation plans that are too detailed for
the main documentation. Specs are optional working documents, not required AI workflow
files and not immutable architecture contracts.

## Template

# Feature: <name>

## Problem
- What user or system pain this solves.

## Non‑Goals
- What is explicitly out of scope.

## Behavior Rules
- Rules the system must follow (no implementation details).

## Edge Cases
- Inputs or conditions that could break naive logic.

## Risks
- Architecture or performance risks.

## Test Plan
- New tests required.
- Existing tests that must pass.

## Acceptance Checks
- Observable behaviors that confirm success.
