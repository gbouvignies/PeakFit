# Linked Save and explicit portable analysis export

Standard Save and Save as now publish linked `.peakfit` analyses. Export portable
analysis creates a separate self-contained snapshot using the same serializer,
atomic manifest publication, evidence reader and scientific verification checks.
Scientific exports, their defaults, terminal corrections and GUI/CLI parity are
unchanged. Project writes use schema 4.0.0; previous PeakFit versions cannot read
it. Existing older project readers remain, with no new compatibility adapters.

## Scientific retention decision

Keep detailed sampled observations and historical predictions in both modes.
The linked project is approximately **16.86 MB**, rather than the audit's
source-dependent **7.11 MB** alternative. The additional ~9.75 MB buys review of
observations, historical models and terminal residuals without the source or a
future evaluator matching historical arithmetic. Terminal corrections, paired
sample indices, exact plane identities, fitted values/uncertainties, initial and
adopted coordinates, diagnostics and provenance remain unchanged. Residual arrays
are regenerated by the existing validated operation order; dense full-grid models
remain disposable. No refitting or amplitude solve occurs on reopening.

The smaller alternative would require another reconstruction/capability path,
make missing-source sample review unavailable, and lose the original computed
prediction bits. That tradeoff is unnecessary for a reliable working project.
The retained detailed evidence is deliberately independent of the optional full
cube. Source-free numerical review is distinct from source-free spectral work.

Linked reopen verifies the recorded spectrum's SHA-256, scientific calibration,
shape/dtype and exact source-plane/sample mapping. Recorded relative and absolute
locations are tried; a separately moved file requires explicit Relink source.
Changed/corrupt/unreadable sources never replace scientific evidence. Missing
sources retain valid numerical review and export; spectral inspection, adjustments
and fitting are unavailable. Current/Outdated status remains a scientific fact,
independent of source availability.

Portable export embeds all original-dtype experimental values, including those
outside fitting masks. Reopening it needs neither the spectrum nor the original
peak/plane-value files. It permits full spectral views and subsequent adjusted
fitting. Export does not change the editor's path or saved/unsaved status and
requires a new destination. Standard Save of an opened portable project publishes
linked state and only then removes the cube; Save as also creates linked state.
Export portable analysis is the explicit way to create another portable snapshot.
Recovery checkpoints use linked projects and retain detailed numerical evidence.

## Measurements

Real bundled `pseudo3d.ft2`, `pseudo3d.list` and `b1_offsets.txt`: 166 peaks,
121 clusters, 131 planes, two fitting passes. Cube `(131,256,546)`, float32;
73,242,624 numerical bytes. macOS arm64, Python 3.14.5, NumPy 2.4.1, one BLAS
thread. Baseline uses merged `80d66fd` code. Three fresh processes per revision,
sequential runs on the same machine; medians below, logical decimal MB. Raw
[measurements](project-portability/measurements.json) retain every run, phase and
process RSS. Source copies and temporary projects are removed after validation.

| One completed run | Merged default | Linked standard Save | Portable export |
| --- | ---: | ---: | ---: |
| Project size | 85.248 MB | **16.856 MB** | 85.248 MB |
| Embedded experimental cube | 68.392 MB | **0** | 68.392 MB |
| Two analyses, project bytes only | 170.497 MB | **33.712 MB** | 170.497 MB |

Each linked analysis references the same external spectral file; there is no
shared-asset registry or copied cube. Relative links survive moving source and
analysis together. Immutable run evidence is still owned by each analysis.

| Operation | Merged default (s) | New policy (s) |
| --- | ---: | ---: |
| Fit completion → durable acceptance checkpoint | 2.459 | **1.024** |
| First Save after durable acceptance | 0.0758 | **0.0181** |
| Routine Save | 0.0082 | **0.0083** |
| Save as another analysis | 0.0756 | **0.0177** |
| Verified reopen | 0.6217 | **0.5247** |
| Portable reopen without originals | 0.6883 | **0.6142** |

New portable export from a linked analysis takes **1.398 s**: it performs the
embedding deferred from ordinary acceptance/Save. The baseline's equivalent
Save as took 0.0746 s because it merely copied a cube already compressed during
acceptance. Routine Save is effectively unchanged. First Save means publication
from the already durable accepted evidence, as in the real GUI; acceptance is
reported separately. These are warm-cache local measurements, not filesystem or
network latency guarantees. Sub-second changes should not be overinterpreted.

### Publication memory

RSS was sampled every 25 ms for the workload process and all descendants,
excluding the measurement monitor. The durable-publication phase includes IPC,
archive child, compression and process overlap. Median summed RSS decreased from
**1,533 MB to 1,241 MB** (about **19%**). Ranges were 1,533–1,535 MB before and
1,236–1,267 MB after. At the sampled maximum:

- Archive child: approximately **478 MB → 260 MB**.
- Parent: approximately **1,034 MB → 960 MB**; allocator history affects this.
- Multiprocessing resource tracker: approximately 21 MB in both cases.

Most of the decrease is in the temporary archive process: linked saves and
acceptance no longer serialize/transfer/compress a full experimental cube. That
process is reaped after publication. The original source remains resident in the
live GUI for spectral work. This change does not promise to release all Python/
NumPy allocator memory or reduce the fitting engine's allocations. Summed RSS can
count shared pages more than once, and sampling may miss short spikes; these are
RSS observations, not unique physical-memory or allocation counts.

The separate native source-free adjust/refit exercise peaked at 3.03 GB summed
RSS while the driver intentionally retained original and several reopened
projects as well as the active Qt workspace and fit child. It is not an isolated
single-window memory benchmark or evidence of a persistent publication leak.
No speculative memory-management refactor was introduced.

## Validation

- Linked and portable project scientific round trips preserve exact sample values,
  terminal corrections, fitted outcomes/uncertainties and working transitions.
- Missing/unreadable, moved, same-size/same-mtime changed and corrupt external
  spectra retain numerical evidence; explicit matching relink restores access.
- Two analyses share one source without embedded data; relinking one does not
  silently relink the other. Updated links persist on Save.
- Both source modes check retained fitting-plane identity, including exclusions
  and repeated experimental values, through one shared verification function.
- Portable source-free reopen preserves every experimental value; native Cocoa
  model and residual views work. Moving a peak makes the result Outdated; an
  actual adjusted fit restores Current. The native refit took 6.33 s in this run.
- Portable export preserves the editor path and unsaved edits; it cannot overwrite
  a linked analysis or invent a full cube from retained samples.
- Atomic failure/cancellation retains the previous committed generation, including
  failure while converting an embedded project to linked state. Existing bounded
  history, crash recovery, lazy loading and ownership tests remain applicable.
- Scientific round-trip, continuation and cross-interface export parity tests run
  with the project tests. Standard GUI/CLI scientific writers were not modified.

Reproduction:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 uv run python \
  tools/validate_project_portability.py --output /tmp/portability.json --native
```

The same driver runs against merged source via `PYTHONPATH` to obtain the baseline;
it detects that the old serializer always embeds data. Native validation is
additional to the three matched storage/timing runs. The benchmark imports the
existing native model/residual/refit exercise instead of adding a GUI harness.

Final checks: **496 tests passed** with `QT_QPA_PLATFORM=offscreen MPLBACKEND=Agg
uv run pytest -q`. Ruff, repository formatting, strict `ty check --error-on-warning`
and both import-linter contracts pass. Graphify's code graph was updated. The
native Cocoa workflow is separate from the offscreen suite.
